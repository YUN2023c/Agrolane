# Geo 召回与 LBS 推荐设计说明

本文给出 Agrolane 农道空间检索的设计推导、参数依据与参考来源。README「方法论」只列结论，这里补充为什么这样设计、以及换成 PostGIS 时对应哪一层。

## 1. 问题定义

给定检索原点 `(lat, lng)`、半径 `r`、品类 `catId`、数量 `qty`、供货月份 `months`，从供方台账中返回满足硬条件的候选，并按可解释分数排序。

约束：

- 县域级数据，万级主体，单机 SQLite，不部署空间数据库。
- 原点由用户手输，不依赖设备定位；距离必须可复算、可审计。
- 地理条件只做过滤，不能变成隐性打分项——否则"距离近"会悄悄压过品质与信用。

## 2. 两段式空间检索

### 2.1 为什么不用 `ORDER BY haversine(...)`

haversine 是标量函数，写进 `WHERE` 或 `ORDER BY` 都无法走索引，最终退化成全表计算 + 排序。万级数据尚可，十万级就会拖垮单机。

改为两段：

1. **粗召回**：用 geohash 前缀区间扫描筛出小候选集，走 B-tree 索引。
2. **精算**：只对候选算 haversine，按半径硬过滤。

粗召回允许多召回（假阳性），不允许漏召回（假阴性）。

### 2.2 半径 → 精度映射

geohash 每加一位，格子边长约缩小 6 倍（经度方向）。精度选"格子对角线略小于半径"的档位：

| 半径 | 精度 | 格子近似尺寸 |
|---|---|---|
| ≤ 3 km | 6 | 约 1.2 × 0.6 km |
| ≤ 12 km | 5 | 约 4.9 × 4.9 km |
| ≤ 60 km | 4 | 约 39 × 19.5 km |
| ≤ 250 km | 3 | 约 156 × 156 km |

### 2.3 覆盖格枚举

只查原点所在格会漏掉边界外的点。做法：

1. 算半径外接矩形 `bboxForRadius(lat, lng, km)`。
2. 按选定精度，枚举矩形覆盖的全部 geohash 前缀格。
3. 格数上限 64，超出则降一级精度重算——避免 SQL 里 OR 条件爆炸。

### 2.4 前缀区间扫描

对每一格生成一个闭区间：

```sql
geohash >= ? AND geohash <= ?
-- 参数：[prefix, prefix + '\uffff']
```

多格之间用 `OR` 连接。`geohash` 列建普通索引即可命中 range scan，不需要专门的 R-Tree。

### 2.5 复杂度

| 阶段 | 复杂度 | 说明 |
|---|---|---|
| 前缀扫描 | O(log N × G) | G = 覆盖格数，≤64 |
| haversine 精算 | O(C) | C = 候选数，远小于 N |
| 排序 | O(C log C) | 候选集内排序 |

## 3. 三路召回 + RRF

单一通路有偏：geo 只看距离，content 不看地域，hot 只认热度。三路并行取候选，用排名融合而不是分数融合。

| 通路 | 取数逻辑 | 解决的问题 |
|---|---|---|
| geo | 半径内 + 品类匹配 | 近处优先 |
| content | 全量同品类（可带品种过滤） | 不漏远处优质货源 |
| hot | 同品类按成交量与信用排序 | 冷门品类兜底 |

融合用 Reciprocal Rank Fusion：

```text
RRF(d) = Σ  1 / (k + rank_i(d))
        i∈通路
```

- `k = 60`，沿用原论文常用值。
- 只用排名，不用分数——geo 的距离、content 的相似度、hot 的成交量量纲不同，归一化反而引入调参。
- 某通路未召回的候选，该通路不贡献分数，不需要补 0。

RRF 的原始出处：Cormack, Clarke, Buettcher. *Reciprocal Rank Fusion Outperforms Condorcet and Individual Rank Learning Methods*. SIGIR 2009, pp. 758–759. DOI: 10.1145/1571941.1572114.

## 4. 硬过滤与放宽

RRF 之后按业务条件硬过滤：品类、数量产能、供货月份、资质、半径、报价状态。

过滤是布尔判定，不进打分器。零结果时不做静默放宽，而是逐级累计试跑并回传建议：

1. 放大半径。
2. 去掉品种限定。
3. 放宽月份。
4. 降低产能要求。

每一级都在前一级基础上累加，因为实际常见"月份 + 产能"同时卡住，单放一维仍为零。前端展示的是最终可出结果的那组累计参数。

## 5. 可解释排序

```text
total = 0.40 × 加权余弦(10 维)
      + 0.25 × (履约率 × 0.6 + 信用分 × 0.4)
      + 0.20 × 价格适配度
      + 0.15 × 地域分
      + 规则加成
```

| 维度 | 含义 |
|---|---|
| 一级率 | 一级品占比 |
| 产能匹配 | 可供量与需求量比值 |
| 报价存在性 | 是否已录入报价 |
| 综合信用 | 台账信用分 |
| 履约率 | 历史履约 |
| 地域分 | 距离衰减 |
| 三项认证 | 认证标记命中数 |
| 品种命中 |  requested 品种匹配 |

余弦相似度前先对向量去均值，避免某条记录的独热维度把整体相似度抬高。

规则加成：滞销助农 +10、有成交 +5、同区域 +3、兴趣权重 ×2。

分数不是黑箱：结果卡片展示五维子分、召回通路、匹配理由与风险提示。"低于报价均值 12%"这类文本由实时报价聚合算出，不预置。

## 6. LBS 推荐流

```text
score = wI × 兴趣 + wD × exp(-距离/λ) + wQ × 质量 + wF × 时效
```

| 项 | 来源 |
|---|---|
| 兴趣 wI | `interactions` + `favorites` 的品类分布 |
| 距离 wD | haversine，指数衰减，λ 默认 60 km |
| 质量 wQ | 履约率与信用 |
| 时效 wF | 最近更新时间 |

冷启动策略：无行为画像时，把兴趣权重让给距离/质量/时效，而不是把兴趣分置 0 后仍保留其权重——后者会整体压低所有候选的分数，排序失去区分度。

同品类最多 2 条，避免整屏单一品类。

## 8. 迁移到 PostGIS

数据量上到百万级或需要复杂空间关系时，把第二段换成 PostGIS，第一段的设计思路保留：

| 当前实现 | PostGIS 对应 |
|---|---|
| geohash 列 + 前缀区间 | `geometry(Point,4326)` + GiST 索引 |
| 前缀枚举 | `ST_DWithin(geom, origin, r)` |
| haversine 精算 | 已包含在 `ST_DWithin`（ geography 类型按米计算） |
| 覆盖格上限 64 | 无需，R-Tree 自动处理 |

业务过滤、RRF、排序与解释层与存储无关，不需要改。
